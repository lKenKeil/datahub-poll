# ASKIO 공식 발행 계정

투표 상세 화면은 공개 작성자의 닉네임을 표시합니다. 서버 설정에 지정된 Auth 계정의 공개 투표에는 고정 표시 이름 `ASKIO 공식`, 기존 B1 심벌, `공식 운영 계정` 배지를 표시합니다. 표시를 열면 공식 계정 소개를 볼 수 있습니다. 작성자 UUID, 이메일, 프로필 설정을 공개하지 않습니다. 익명 발행과 작성자 없는 기존 투표에는 작성자 줄이 표시되지 않습니다. 기존 `공식 데이터 기반` 분류는 그대로 사용합니다.

## 검증 환경 설정

1. 개발 또는 스테이징 앱에서 운영팀이 관리하는 별도 이메일로 이메일 OTP 가입·로그인을 완료합니다. 인증 정보는 승인된 계정 관리 절차로 보관합니다. 개인 계정에서 운영용 로그인 수단을 연결하거나 관리자 키를 공유할 필요는 없습니다.
2. 대상 Supabase 프로젝트의 Authentication → Users에서 직접 로그인한 계정의 사용자 ID를 확인합니다. 같은 환경의 앱 서버에만 `ASKIO_OFFICIAL_ACCOUNT_USER_ID`를 설정합니다. 개발과 운영의 ID를 각각 확인하고 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.
3. 기존 Auth 세션 검증, `polls.author_user_id`, `polls.is_anonymous`, `poll_ownership`, 서비스 역할의 읽기 권한 및 기존 RPC가 대상 환경에 적용되어 있는지 확인합니다. 이번 기능에는 신규 SQL이나 RLS 변경이 없습니다.
4. 공식 계정으로 `/create`에서 테스트 투표를 작성하고 `익명으로 올리기`를 해제합니다. 작성한 브라우저에서 관리 토큰을 유지합니다. 별도 브라우저에서 로그아웃 상태의 작성자 표시와 투표, 새로고침, 그리고 일반 계정의 수정·삭제 거부를 확인합니다. 공식 계정은 해당 투표의 기존 관리 토큰을 함께 제출해야 수정·삭제할 수 있으므로 같은 계정으로 어디서나 관리할 수 있다고 가정하지 않습니다.
5. 운영에서는 전용 계정 등록·서버 설정·코드 적용·콘텐츠 발행을 각각 승인받은 뒤 진행합니다. 3편 혼밥 투표의 문구와 보기는 발행 전에 검토하고, 생성된 공개 URL을 로그아웃 창과 모바일에서 확인한 뒤 블로그에 연결합니다.

## 계정 교체와 기존 투표

서버 설정은 하나의 계정 ID를 가리킵니다. 값을 바꾸면 공식 표시와 공식 투표의 계정 세션 검사가 새 ID로 전환됩니다. 값을 제거하면 공식 배지가 사라지고 해당 투표는 이전 브라우저 토큰 검증으로 돌아갑니다. 계정 교체와 설정 롤백 시 기존 관리 토큰의 범위를 함께 검토합니다.

1·2편은 기존 링크를 유지합니다. 소유권 검토가 승인되면 먼저 블로그의 실제 링크에서 투표 ID를 확정하고, 권한 있는 담당자가 해당 ID의 현재 작성자와 관리 토큰 행 존재 여부를 읽기 전용으로 확인합니다. 작성자만 수정해도 기존 관리 토큰이 살아 있을 수 있으므로, 이전은 기존 토큰 폐기·새 관리 토큰 발급·감사 기록을 포함한 별도 작업입니다. 이전 전후에 같은 공개 URL, 투표 집계·기록·댓글과 잠금 상태를 비교하고, 스테이징에서 원 작성자의 권한 복원과 새 토큰 폐기를 포함한 롤백을 검증합니다. 이 브랜치에는 이전 SQL이 없습니다.
